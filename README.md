# Управление коллекцией лабораторных работ

Учебное клиент-серверное приложение на Java для управления записями о лабораторных работах. Пользователь работает через консольный клиент: регистрируется, добавляет записи, просматривает коллекцию и изменяет собственные элементы. Сервер принимает команды по UDP и хранит данные в PostgreSQL.

Проект развивает [консольную версию приложения](https://github.com/ckek4095/work_with_collections): обработка команд и хранение данных вынесены на сервер, добавлены сетевой обмен и учётные записи пользователей.

Приложение хранит сведения о работах; автоматическая проверка студенческих решений в его задачи не входит.

## Возможности

- Регистрация и вход с логином и паролем.
- Добавление, просмотр, обновление и удаление записей.
- Проверка владельца при обновлении и удалении отдельных записей.
- Фильтрация по дисциплине и началу названия.
- Условное добавление по минимальному баллу.
- Просмотр последних 12 команд.
- Выполнение команд из текстового файла.
- Хранение пользователей и лабораторных работ в PostgreSQL.
- Обработка запросов с использованием пулов потоков.

## Технологии

| Область | Используемые технологии |
| --- | --- |
| Язык и сборка | Java, Maven, многомодульный проект |
| Сетевой обмен | UDP, `DatagramSocket`, JSON в UTF-8 |
| Сериализация | Gson |
| Хранение данных | PostgreSQL, JDBC, `PreparedStatement` |
| Консольный интерфейс | JLine |
| Обработка запросов | `ExecutorService`, `ForkJoinPool` |

## Архитектура

```text
Консольный клиент
      |
      | UDP / JSON
      v
Сервер команд
      |
      | JDBC
      v
  PostgreSQL
```

Клиент разбирает команду, при необходимости запрашивает поля лабораторной работы и формирует объект `Request`. Сервер десериализует запрос, проверяет учётные данные, выбирает реализацию команды и возвращает ответ в JSON.

Команды представлены отдельными классами. Сопоставление названий команд и их реализаций находится в `CommandType`, а операции с базой данных — в `DatabaseManager`.

## Модель данных

Запись `LabWork` содержит идентификатор, название, координаты, дату создания, минимальный балл, сложность, сведения о дисциплине и идентификатор владельца.

Уровни сложности: `EASY`, `NORMAL`, `HARD`, `VERY_HARD`, `INSANE`.

## Локальный запуск

Текущая версия требует ручной подготовки PostgreSQL. Docker Compose и готовый дистрибутив приложения пока не добавлены. Ниже описан запуск из IDE после настройки базы данных; это не инструкция запуска готового JAR.

### 1. Подготовить окружение

Понадобятся JDK, Maven, PostgreSQL с клиентом `psql` и IDE с поддержкой Maven.

В текущих `pom.xml` используются целевые версии Java 11 и 15. Для локальной настройки можно использовать JDK 17; параметры SDK проекта и Maven runner должны быть согласованы. Приведение всех модулей к единой целевой версии входит в план доработок.

```bash
git clone https://github.com/ckek4095/work_with_collections2.git
cd work_with_collections2
```

Открыть корневой `pom.xml` как Maven-проект и загрузить зависимости всех трёх модулей.

### 2. Подготовить PostgreSQL

В `server/src/main/java/org/example/ServerConfig.java` заданы параметры подключения:

```text
URL:         jdbc:postgresql://localhost:5432/testdb
Пользователь: postgres
Пароль:       postgres
```

Изменить их под локальное окружение. Отдельного SQL-скрипта инициализации в репозитории пока нет. Ниже приведена минимальная схема, составленная по запросам текущего `DatabaseManager`; её нужно выполнить в отдельной базе `testdb`.

Создать базу, если её ещё нет:

```bash
createdb -h localhost -U postgres testdb
psql -h localhost -U postgres -d testdb
```

Выполнить в `psql`:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    login TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL
);

CREATE TABLE lab_works (
    id BIGSERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    coord_x INTEGER NOT NULL,
    coord_y INTEGER NOT NULL,
    creation_date TIMESTAMP NOT NULL,
    minimal_point REAL NOT NULL,
    difficulty TEXT,
    discipline_name TEXT NOT NULL,
    discipline_labs_count INTEGER NOT NULL,
    user_id INTEGER NOT NULL REFERENCES users(id)
);
```

`BIGSERIAL` создаёт последовательность `lab_works_id_seq`, которую использует сервер при добавлении записей. Пользователя приложения нужно регистрировать через клиент; напрямую добавлять пароль в таблицу не требуется.

### 3. Запустить сервер

В IDE запустить `org.example.MainServer` из модуля `server`.

Сервер подключается к PostgreSQL и открывает UDP-порт `60000`. Если подключение к базе не установлено или таблицы отсутствуют, инициализация завершается с ошибкой.

### 4. Запустить клиент

В отдельной конфигурации IDE запустить `org.example.MainClient` из модуля `client`. Если консоль IDE не поддерживает ввод JLine, использовать её терминал или конфигурацию с эмуляцией терминала.

Клиент по умолчанию подключается к `localhost:60000`. Адрес и порт заданы в `MainClient`, порт сервера — в `UDPInitialization`.

Зарегистрироваться:

```text
register demo_user
```

Пароль вводится по отдельному приглашению. Для существующего пользователя:

```text
auth demo_user
```

В текущей реализации логин должен содержать не менее 3 символов, пароль — не менее 4.

## Команды

Все команды работы с коллекцией требуют авторизации. Поля элемента для `add`, `add_if_min`, `add_if_max` и `update <id>` можно вводить интерактивно.

| Команда | Назначение |
| --- | --- |
| `register <login>` | Зарегистрировать пользователя; пароль запрашивается отдельно |
| `auth <login>` | Войти; пароль запрашивается отдельно |
| `help` | Вывести встроенную справку |
| `info` | Показать тип коллекции и количество элементов |
| `show` | Показать все записи |
| `add` | Добавить запись |
| `update <id>` | Обновить собственную запись |
| `remove_by_id <id>` | Удалить собственную запись |
| `clear` | Удалить записи текущего пользователя |
| `add_if_max` | Условное добавление по максимальному минимальному баллу |
| `add_if_min` | Условное добавление по минимальному минимальному баллу |
| `filter_by_discipline <name>` | Найти записи по названию дисциплины |
| `filter_starts_with_name <prefix>` | Найти записи по началу названия |
| `remove_all_by_minimal_points <value>` | Удалить собственные записи с указанным минимальным баллом |
| `history` | Показать последние 12 команд |
| `execute_script <path>` | Прочитать локальный файл и передать команды серверу |
| `exit` | Завершить работу клиента |

Таблица отражает названия из текущего диспетчера команд. Встроенная справка содержит устаревшие упоминания файлового сохранения и другое написание `remove_all_by_minimal_point`; для этой версии нужно использовать `remove_all_by_minimal_points`.

## Пример работы

После регистрации или входа:

```text
help
info
add
show
filter_by_discipline Программирование
history
exit
```

После `add` клиент последовательно запросит название, координаты, минимальный балл, сложность, название дисциплины и количество лабораторных работ. Для обновления и удаления нужно использовать идентификатор из вывода `show`.

Простой файл для проверки выполнения скриптов:

```text
info
show
history
```

Сохранить его как `demo.txt` в рабочем каталоге клиента и выполнить `execute_script demo.txt`. Вложенные вызовы `execute_script` сервер пропускает.
